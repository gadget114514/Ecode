# OSC 1337 (iTerm2 Inline Images Protocol) 実装計画

## 概要

iTerm2 が策定した独自エスケープシーケンス OSC 1337 を Ecode ターミナルに実装する。
主に Inline Images Protocol をターゲットとし、加えてファイルダウンロード・Multipart 転送に対応する。

## プロトコル仕様

### 基本パターン
```
ESC ] 1337 ; Key = Value BEL/ST
```

### File 転送 (2モード)

#### 通常モード
```
OSC 1337 ; File = [opts] : [base64_data] BEL
```

#### Multipart モード (tmux 統合, iTerm2 3.5+)
```
OSC 1337 ; MultipartFile = [opts] BEL        # 開始
OSC 1337 ; FilePart = [base64_chunk] BEL      # 分割データ (N回)
OSC 1337 ; FileEnd BEL                         # 終了
```

### File オプション

| Key | 型 | デフォルト | 説明 |
|---|---|---|---|
| `name` | base64文字列 | `"Unnamed file"` | ファイル名 |
| `size` | 整数(バイト) | 省略可 | プログレス表示用 |
| `width` | N / Npx / N% / auto | auto | 表示幅 |
| `height` | N / Npx / N% / auto | auto | 表示高さ |
| `preserveAspectRatio` | 0 or 1 | 1 | アスペクト比維持 |
| `inline` | 0 or 1 | 0 | 1=インライン表示, 0=ダウンロード |

## アーキテクチャ

### データフロー
```
ConPTY reader thread
  → PostMessage(WM_TERMINAL_OUTPUT)
    → TerminalEmulator::process(utf16)
      → handleOsc() [case 1337]
        → base64 decode
        → onImageData_ callback (image bytes + options)
          → TerminalView::OnImageData()
            → ImageManager::DecodeAndStore()
              → WIC decode → ID2D1Bitmap
              → return imageId
            → buffer_.placeImage(row, col, imageId, width, height)
              → image occupies N×M cells (like wide cells)
    → InvalidateRect()
      → OnPaint()
        → DrawCell() [imageId != 0 → DrawBitmap()]
```

### 画像のセルグリッド配置モデル (Inline Cell-Based)

- 画像はカーソル位置から、指定された幅×高さ（セル単位）の矩形を占有する
- 占有セルは `imagePlaceholderIndex` で管理（0 = 左上, 1..n = 継続セル）
- `wide`/`wideContinuation` と同様のパターンでセル占有を表現
- 画像の後ろのテキストは改行されて下に流れる
- スクロール・行挿入・行削除時に画像セルも追従する

### 画像サイズ計算

```
width指定              → ピクセル換算
  N                   → N × cellWidth
  Npx                 → N ピクセル
  N%                  → viewport幅 × N/100
  auto                → 元画像のピクセル幅

height指定             → ピクセル換算
  同上

セル数 = ピクセル / cellSize (切り上げ)
preserveAspectRatio=1 → アスペクト比を維持して収まるようにサイズ調整
```

## 注意点

1. **D2Dデバイスロス**: `D2DERR_RECREATE_TARGET` 発生時は `ImageManager` も全 `ID2D1Bitmap` を再作成 (`rawData` から再デコード)
2. **パフォーマンス**: 全面再描画方式のまま。後に dirty rect 最適化を検討
3. **メモリ制限**: 画像の生データを保持するため、上限（最大画像数 or 最大メモリ）を設定
4. **対応フォーマット**: PNG/JPEG/GIF/BMP (OS/WICがサポートする全形式)
5. **アニメーションGIF**: 初回フレームのみ表示（アニメーションは未対応）
